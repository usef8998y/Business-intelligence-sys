# Engineering Rules — Retail BI MVP

## Product boundaries
- This repository contains the Retail Business Intelligence MVP only.
- Do not add Horus/geospatial features or unrelated modules.
- Do not claim that a feature exists unless it has been implemented and tested.

## Architecture
- Use the agreed frontend, backend, and PostgreSQL architecture.
- Follow the approved data model, metric definitions, and API contracts.
- Do not change shared contracts without approval from the integration owner.

## Data and analytics
- Business metrics must be deterministic and tested against known expected values.
- Never invent missing costs, historical stock levels, evidence, or business results.
- Report insufficient data explicitly.
- Never execute arbitrary SQL generated by an LLM.

## Development workflow
- Inspect relevant files before editing.
- Make small, scoped changes on a separate Git branch.
- Add tests for new behavior and important failure cases.
- Run the relevant tests and build before opening a pull request.
- Report the exact commands run and their actual results.
- Do not commit secrets, API keys, or real customer data.

## Pull requests
- Explain the purpose and scope of each change.
- List files changed, tests run, and known limitations.
- Obtain human review before merging into the main branch.
